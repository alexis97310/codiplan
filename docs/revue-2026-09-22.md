### T-04 — CI qui tourne deux fois, filtre du bot Vercel
**Verdict : PARTIEL — deux points sur trois déjà traités ; le troisième instruit et NON réalisé ce jour.**

1. **Le double passage PR + main n'est pas une duplication accidentelle** : c'est l'arbitrage D14 documenté en tête de `ci.yml` (« deux portes : `verify` à chaque poussée, `verify:full` sur `main` et chaque nuit »). Le bloc `concurrency` (`group: ${{ github.workflow }}-${{ github.ref }}`) sépare déjà correctement PR et push sur `main` — rien à corriger.
2. **Le filtre `vercel[bot]` est déjà en place, intégralement.** Les quatre déclencheurs de `claude.yml` (`issues`, `issue_comment`, `pull_request_review_comment`, `pull_request_review`) exigent tous `author_association == 'OWNER'` (lignes 82-86). Un commentaire automatique de Vercel (association `NONE` ou équivalente) est déjà écarté sur les quatre chemins. **Ce sous-point du constat est infirmé.**
3. **`paths-ignore` est réellement absent** de `ci.yml` (confirmé, aucune ligne `paths`/`paths-ignore` dans le bloc `on:`). Un commit qui ne touche que `docs/` relance donc `verify`/`verify:full` en entier.

**Pourquoi ce point n'a pas été réalisé aujourd'hui, malgré le mandat qui l'autorisait « si sans risque » :** ajouter un `paths-ignore` sur un workflow qui pose des *status checks* peut laisser une pull request « docs seulement » bloquée en attente si les règles de protection de branche exigent nommément `verify`/`verify:full` comme checks requis — GitHub gère ce cas depuis 2021, mais seulement si aucune exécution passée du même nom de check ne traîne, et je n'ai pas accès aux réglages de protection de branche pour vérifier (le mandat interdit par ailleurs de toucher aux réglages GitHub). **Recommandation : vérifier les règles de protection de `main`, puis ajouter `paths-ignore: ["docs/**"]` en un commit isolé, testé sur une PR docs-only avant généralisation. Taille : S.**
